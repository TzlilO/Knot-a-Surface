# Publishing Knot-a-Surface

Pages for this repo is served from **main → / (root)**. There is **no bundle step**:
the deployed pages are the `.dc.html` design files flattened to flat filenames by
`deploy/flatten.py`, loading `support.js`, the `_ds/` design tokens and the `src/`
simulator cores as sibling files. A root `.nojekyll` is required (Pages would
otherwise skip `_ds/`).

## Publish

```bash
cd /path/to/Knot-a-Surface        # local clone, main branch
bash deploy/deploy-site.sh        # flatten + rebuild deck/arena + commit + push
# deploy-review.sh is an alias left for muscle memory — same script
```

Live in ~1 min. Hard-refresh or add `?v=N` (Pages cache-control is 600 s).

## Workflow

1. Edit the `.dc.html` design files (page chrome) or `src/` (simulator cores).
2. If `src/sim_core.js` / `src/sim_style.css` changed, `build.py` refreshes the
   inlined copies inside `deck.html` (terrain.html sibling-loads them — nothing
   to rebuild for the site itself).
3. `bash deploy/deploy-site.sh` — flattens, rebuilds, commits, pushes.

The site root `index.html` is NOT a flatten output: it is the hand-written landing page
(see the repo README). Never edit the flattened outputs (`project-page.html`, `terrain.html`, `review/…`) by
hand — edit the `.dc.html` source and re-flatten.
