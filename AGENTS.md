# Knot-a-Surface — Agent Guide

## Project overview

Knot-a-Surface is a static-site project demonstrating a thesis idea: **NURBS-grounded
Gaussian splatting** — splat positions are never free in 3D; they are derived from a
single (u,v) parametrization of the underlying surface. The repo contains several
self-contained single-file HTML apps that run in a browser:

- `index.html` — **Landing page** (hero, embedded teaser, sim cards, method, measured
  Results section). Flattened from `Project Page.dc.html` by `deploy/flatten.py`.
- `terrain.html` — **Swarm Resolution-Knob Simulator** (Sim v1): a drone swarm
  reconstructs battlefield terrain as a spline-coupled splat surface under a fixed
  Gaussian budget. Flattened from `Sim v1 - Swarm Core.dc.html`; sibling-loads
  `src/sim_core.js` + `src/sim_style.css`.
- `terrain-atlas.html` / `knot.html` / `surface-prior.html` — Sims v2/v3/v4 (UV-atlas
  editing, knot chart, Surface Prior bench). Flattened from the matching `.dc.html`.
- `teaser-{v1,bold,modest,cinematic}.html` — the four teaser cuts (flattened).
- `review/index.html` — review hub (flattened, deployed-link mode, `../` paths).
- `arena.html` — **Arena**: live 4D match reconstruction. Same thesis applied to a
  sports court (basketball/football) with a *fixed* broadcast-camera swarm; the point
  is free-flying inside the live reconstruction (WASD + pointer-lock mouse).
- `deck.html` — reveal.js interview deck that embeds the same simulator as slide 14.
- `v4.html` — hand-written sampler lab for the uvUniform/uvAdaptive (u,v)-atlas samplers
  (sibling-loads `src/sim_v4_core.js`).
- `project.html` — retired predecessor landing page with its own local token set
  (deliberately different values; don't force the shared tokens onto it). Live but
  unlinked.

Live site (GitHub Pages): https://tzlilo.github.io/Knot-a-Surface/ · `/terrain.html` · `/surface-prior.html` · `/review/`

## Technology stack

- **No npm, no bundler, no framework, no test suite on disk.** Everything is static
  HTML/CSS/JS served as-is.
- three.js (`three@0.158.0`, non-module build), reveal.js, KaTeX, Chart.js and fonts
  (Inter, Space Grotesk, JetBrains Mono) load from CDNs (jsDelivr / Google Fonts).
- The only build tools are `build.py` and `deploy/flatten.py` (Python 3, stdlib only).
- Simulator cores are plain browser-global IIFEs: `window.KnotSwarmSim`,
  `window.KnotArenaSim`, `window.KnotSurfacePrior`.

## Build & run

```bash
python3 deploy/flatten.py   # .dc.html designs → deployed pages (index.html, terrain.html, …)
python3 build.py            # src/ parts → deck.html + arena.html
```

`build.py` injects `src/` parts into the deck/arena templates at the marker comments and
stamps `/*__BUILD_TIME__*/` in `sim_core.js`. `deploy/flatten.py` is link-rewrites only —
the deployed pages sibling-load `support.js`, the `_ds/` tokens and the `src/` cores, so
editing a core needs no rebuild for the site (only `build.py` for deck/arena). Everything
runs over any static server (`python3 -m http.server 8000`).

## sim_core.js architecture (one IIFE, ~4.3k lines)

Module scope: `hash2/vnoise/fbm` noise · env definitions `ENVS.{urban,forest,ocean,dust}`
with `h(x,z,t)` occupancy + `col(x,z,h,t)` albedo · `bicubic()` = switchable basis
(CR default / clamped B-spline p2-5 / NURBS rational, module var `BASIS_DEG`).
`create(container,{embed})` closure holds everything else:

- **fit model** — control grid of heights `fit{CN,cur,tgt,res,crop,x0,z0}`; `sampleTarget`
  (4-tap max supersampling), `optimStep` (time-based rate, Laplacian REG=0.3, weighted by
  `covW` swarm coverage × `peW` photometric, plus bidirectional-Chamfer `GEO` when
  `st.geoSup`), `computeWeights`, `truncSubdivStep` (error-driven subdivision), warm-up
  levels `WARM_LEVELS`, `reWarm()` on any MODEL change. Control-net UV res = `st.cnet`.
- **sampling modes** — `rebuildImportance`+`axisSample` inverse-CDF warp; `FLU` fluid
  particles with settle/freeze logic in `fluidStep`.
- **recon** — `updateRecon` two-pass (heights `HH`, then NN-stretched splats + facade
  wall-scan); `allocRecon` splits budget into surface S×S + `wallCap` by `wallFrac(pitch)`.
- **views** — main + commander renderers share one scene; layers 0 world / 1 recon /
  2 overlays. `frustumWindow()` = view-driven allocation window (always on). Channels
  RGB/DEPTH/NORMAL/CONF via buffer swap.
- **observer drone** (`st.drone` default on, owns MAIN POV) — `droneStep(dt)` kinematics
  drive `cmdrCam` + `st.roi`; joysticks (`makeStick`) + WASD/arrows/QE; autonomous
  patrol resumes after 5 s idle. Mobile = twin sticks + zen-on-move.
- **swarm** — `updateSwarm`, physical footprints `footF = alt*0.85`; `swarmFoot.pts`
  feeds `computeWeights` (layout matters).
- **commander tools** — ruler+LOS (`surfacePickFrom` ray-march), markers, TACREF
  (`tacQuery`, MGRS-style grid + clipboard), pitch slider, LINK/FREE.
- **segmentation** — `segRun` seeded mean-split + flood-fill on the active channel;
  mask is WORLD-anchored in fixed grid `seg.gmask` (SEG_GW=384 over ±SEG_BND=120 m);
  `applySeg` zeroes per-splat conf outside the mask (revertible).
- **mesh recon** (`st.recon='mesh'`, tri/quad/tetra) — live-stitched indexed mesh from
  the S×S grid; mutually exclusive with fluid sampling.
- **multi-spline** (`SUBS`) — `subFromMask` detaches seg-mask regions into finer
  world-anchored splines; `autoDecompose` bulk-creates top-4; SPLINES dock menu
  (hide/refine/remove). Cleared on env change.
- **export** — `startExport` 2×2 UV-kernel sweep → `buildPLY` binary PLY.
- Debug: `window.__kss = {fit, swarmFoot, st, FLU, topo, seg, grad, drone}` +
  `__kss.segStats()`.

`arena_core.js` (~415 lines) mirrors the same ideas: `COURTS.{basketball,football}`
single-source dims/markings, ground truth = closed `CatmullRomCurve3` loops per player,
`updateSensing` fuses FOV+range-gated detections into 10 Hz ring buffers, `reconAt`
fits an OPEN Catmull-Rom evaluated `LATENCY` (0.22 s) in the past — the rendered
"spline-coupled 4D" estimate (toggle "ghost truth" to compare).

## Invariants — do not break

1. **Field/props single-source**: anything visible in 3D must ALSO be in `h()`/`col()`
   via the SAME deterministic rule (`forestTree`, `FINE.*`, `SITE_BOXES`, `DUST_TROOPS`,
   `patrolPos`, `boatPos`; in arena, `COURTS.*` for floor + minimap). Divergence =
   "invisible to the model" bugs.
2. **Grid structure**: wall-scan, NN-stretch, and PLY 2×2 tessellation assume the S×S
   sampling grid (adaptive warp keeps it; fluid mode bypasses walls deliberately).
3. **All rates time-based** (`1-exp(-K*dt)`), never per-frame — fps varies wildly
   (drone kinematics included).
4. **Weight sources stay separate**: optimization weights come from SWARM views; splat
   allocation window from the COMMANDER frustum. Don't mix them.
5. **Segmentation masks are WORLD-anchored** (`seg.gmask` in fixed world coords),
   never frustum/screen space.
6. **Defaults**: forest env, 64k budget, MANUAL mode, CR basis, ×2 params, adaptive
   sampling, commander-as-main, observer-drone POV on, mesh-supervision (Chamfer) on.

## Testing

There is no automated test suite. Verification is headless-browser smoke testing
(no GPU here — 64k is slow, test at 4k). The swarm sim ships as `terrain.html`,
sibling-loading `src/sim_core.js` — serve the repo and intercept or edit the budget
there, or run the same pattern against `deck.html` (which still inlines the core):

```bash
python3 build.py && python3 -m http.server 8000 &
python3 - <<'PY'
from playwright.sync_api import sync_playwright
with sync_playwright() as p:
    b=p.chromium.launch(args=["--no-sandbox","--headless=new","--disable-gpu","--single-process"])
    pg=b.new_page(viewport={"width":1100,"height":650})
    pg.on("pageerror", lambda e: print("PE:",e))
    pg.goto("http://localhost:8000/terrain.html"); pg.wait_for_timeout(5000)
    pg.screenshot(path="/tmp/t.png"); b.close()
PY
```

Note: headless single-process chromium tends to die when reusing one browser across
many heavy WebGL pages — relaunch the browser per page in sweep scripts.

Rules after every change:

- Re-run `deploy/flatten.py` (if a .dc.html changed) and/or `python3 build.py` (if
  sim_core/sim_style/arena/deck sources changed); syntax-check edited scripts with
  `new Function(...)`.
- Grep the HUD (`.kss-hud-tl`) for expected state; screenshot before shipping.
- Push only with zero console errors (`pageerror` silent).

## Deploy

- **Normal flow**: `bash deploy/deploy-site.sh` (= `deploy/flatten.py` + `build.py` +
  commit + push to `main`). GitHub Pages serves from `main` / root in ~1 min
  (cache-control 600 s — hard-refresh or append `?v=N`). Root `.nojekyll` is required
  or Pages skips `_ds/`.
- `deploy.sh` — one-time repo + Pages setup via `gh` CLI (already done).

  those directories never existed in this repo; the deployed pages are the flattened
  .dc.html files and always reflect `src/`.

## Code style & design conventions

- Plain ES5-ish browser JS in IIFEs exposing a single `window.*` global; no modules,
  no imports, `'use strict'` at the top. Match the existing dense comment-banner style
  (`/* ── section ── */`).
- Deterministic seeded RNG everywhere (`rng(seed)`); no `Math.random()` in sim logic.
- Colors/spacing come from the bound design system — **never invent new colors**.
  Two token groups, do not cross them:
  - **Page palette** (light/dark themable, `--paper/--card/--pcobalt/--pamber/…`) for
    document chrome.
  - **Instrument palette** (always dark, `--instr-*`: bg `#07090f`/`#04070d`, accent
    `#4fc3f7`, warn `#ffa726`, ok `#69f0ae`, danger `#ef5350`, special `#ce93d8`) for
    HUD/instrument chrome (`.kss-*` classes).
  Version accents: v1 green · v2 cyan · v3 purple · v4 amber (the v4 *simulator* chrome
  itself is green `#69f0ae`).
- Type: Inter (UI), Space Grotesk (display), JetBrains Mono (every HUD/badge/readout,
  uppercase, letter-spaced).
- All imagery is procedural canvas/WebGL — no external assets; capture proxies in the
  v4 bench are procedural stand-ins sampled into a shared 300k-point pool.

## Open items / gotchas

1. **v4 bench numbers are measured in-page against procedural proxies** (measureError /
   measureSeries in `src/sim_v4_core.js`) — real measurements of the stand-ins, labeled
   "measured in-page · proxy captures". They are NOT real DTU / Tanks-and-Temples runs of
   the published baseline codebases; keep that caveat visible wherever the numbers appear.
   Primitive counts and DoF ledgers remain exact.
2. Measured values are camera- and budget-dependent (allocation is view-driven); the
   canonical table on the landing page quotes TnT Barn proxy, 12k budget, step 30k,
   default camera, deterministic seed.
3. After syncing with the design side, update `github.md`'s `## Last sync` and
   `## Screen map` as the receipt.
4. Generated/flattened files are never hand-edited: `index.html`, `terrain.html`,
   `terrain-atlas.html`, `knot.html`, `surface-prior.html`, `teaser-*.html`,
   `review/index.html` (flatten.py outputs), `deck.html`, `arena.html` (build.py),
   `support.js` (dc-runtime).
5. The v4 (u,v) atlas samplers (uvUniform/uvAdaptive, exposed in `v4.html`) reconstruct
   visibly worse than transport and cost 30–38 ms/refresh vs 5.8 ms — opt-in lab modes,
   not the default. Known limitation: cube-projection charts keep only the frontmost
   sheet per ray.
